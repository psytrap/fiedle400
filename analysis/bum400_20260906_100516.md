## 4. Dekodierungs- und Dekompressions-Verfahren

1. **7-Bit-Entmaskierung:**
   Bits 7 der Datenbytes 8..28 werden ueber die Maskenbytes 5..7 wiederhergestellt:
   * Bytes 8..14 erhalten Bit 7 aus Byte 5
   * Bytes 15..21 erhalten Bit 7 aus Byte 6
   * Bytes 22..28 erhalten Bit 7 aus Byte 7
2. **Basiswert-Initialisierung (`0xF_` Escape):**
   * Startet ein Byte mit High-Nibble `0xF`, folgt der Basiswert: `BaseValue = ((B1 & 0x0F) << 4) | (B2 & 0x0F)`
   * Im vorliegenden Lauf: SpO2-Basis = `0x61` (97%), Puls-Basis = `0x3F` (63 bpm).
   * Bei `0xFF 0xFF` stoppt die Dekompression (End-of-Session Terminator).
   * Steht ein Basiswert-Nibble am Ende des Subframes (Byte 28), liefert Byte 8 des Folgesubframes die zweite Haelfte (`PendingSplitBase`).
3. **Delta-Nibbles:**
   * High-Nibble: `Sample1 = BaseValue - (B >> 4)`
   * Low-Nibble: `Sample2 = BaseValue - (B & 0x0F)`
   * Ist das Low-Nibble `0x0F`, handelt es sich um ein Füllnibble vor dem Terminator und wird verworfen.
4. **Erkennung von Finger-Out (Kein Signal):**
   * Im Speicherstrom (`0xED`): Out-of-Range Sentinel-Werte:
     * SpO2 <= 0 oder > 100 -> Wert `0x7F` (127 bzw. `---%`)
     * Puls <= 0 oder > 254 -> Wert `0xFF` (255 bzw. `--- bpm`)
   * Im Live-Stream (`0xEB`): Explizites Hardware-Bit `Byte 1, Bit 0` (`(Byte[1] & 1) == 1`).
5. **Zeitreihen-Aggregation (2 Hz -> 1 Hz):**
   * Das Geraet speichert mit 2 Messungen pro Sekunde. Die 243 Rohwerte entsprechen 122 Sekunden.
   * Fuer die Sekundenauswertung wird der Mittelwert der beiden Halbsekunden-Samples gebildet.

## Anhang A: Reversengineering-Dokumentation & Disassembly-Beweise

Dieser Anhang dokumentiert saemtliche Analyseschritte, Disassembly-Auszuege und Register-Ablaeufe aus der Originalsoftware `SpO2.exe`.

### A.1 Master-Paket-Dispatcher & Opcode-Switch-Table
Der zentrale USB-Empfangs-Dispatcher befindet sich bei Virtual Address `0x004c5440`:

1. **Pruefsummen- und Bit-Entmasker:**
   Ruft fuer jeden eingehenden Report `0x004c3c91` auf (`call 0x4c3c91`). Schlaegt die Pruefsumme fehl (`cmp eax, 0`), wird das Paket verworfen.
2. **Opcode-Switch (`0x004c547a` - `0x004c54b4`):**
   Liest `Opcode = packet[0]` und verzweigt ueber eine Jump-Table:
   ```x86
   0x004c547f: mov  al, byte ptr [edx]          ; Opcode
   0x004c548d: sub  ecx, 0xcb                   ; Basis-Offset
   0x004c5499: cmp  ecx, 0x34
   0x004c54ae: mov  dl, byte ptr [eax + 0x4c66d6]
   0x004c54b4: jmp  dword ptr [edx*4 + 0x4c6666]
   ```
   * Opcode `0xEB` (Offset 0x20) -> Index 17 -> Handler `0x004c560d` (Live-Stream)
   * Opcode `0xEC` (Offset 0x21) -> Index 18 -> Handler `0x004c587a` (Session-Header)
   * Opcode `0xED` (Offset 0x22) -> Index 19 -> Handler `0x004c5a79` (Speicher-Subframes)

**7-Bit Integer Packing der Dauer (`0x004c599b` bis `0x004c59e8`):**
```x86

0x004c59c4: mov  al, byte ptr [edx + 0xb]    ; Byte 12
0x004c59c7: shl  eax, 14                     ; eax = Byte[12] << 14
0x004c59ca: or   ecx, eax
0x004c59da: mov  dl, byte ptr [eax + 0xc]    ; Byte 13
0x004c59dd: shl  edx, 21                     ; edx = Byte[13] << 21
0x004c59e0: or   ecx, edx
0x004c59e8: mov  [eax + 0x1a4], ecx          ; Speichert Samples = 243
```
*Beweis:* Das Feld ist kein 16-Bit LE-Wert (`0x73 | (0x01 << 8) = 371`), sondern ein 7-Bit Packed Integer: `0x73 | (0x01 << 7) = 243`!

### A.4 Die Dekompressions-Engine (0x004c4fa7)

1. **Bitmasken-Rueckgewinnung (`0x004c405e` - `0x004c4125`):**
   * Bytes 8..14: `B[i] |= ((Byte[5] << (15 - i)) & 0x80)`
   * Bytes 15..21: `B[i] |= ((Byte[6] << (22 - i)) & 0x80)`
   * Bytes 22..28: `B[i] |= ((Byte[7] << (29 - i)) & 0x80)`
2. **Escape-Erkennung (`0x004c502e`):**
   * `and eax, 0xF0; cmp eax, 0xF0`
   * Bei zwei aufeinanderfolgenden `0xF_` Bytes:
     `BaseValue = ((B1 & 0xF) << 4) | (B2 & 0xF)` (`0x004c50b8`)
   * Bei `0xFF 0xFF` (`0x004c5080` & `0x004c51cb`): Sprung zum Ende (`0x004c52fd`). String-Ressource bei `0x005b6d24`:
     *Unicode: `遇到无效包，结束` ("遇到无效包，结束" = "Ungueltiges Paket angetroffen, Ende").*
3. **Split-Base ueber Paketgrenzen (`0x004c521d`):**
   Tritt `0xF_` bei Index 28 auf:
   * `mov byte ptr [this + 0x3d8], 1` (`PendingSplitBase = 1`)
   * `mov [this + 0x3d4], (B & 0xF) << 4`
   * Beim naechsten Subframe (Index 8) an Adresse `0x004c5144`:
     `BaseValue |= (B_next & 0xF); PendingSplitBase = 0`.
4. **Delta-Nibble Extraktion (`0x004c525f`):**
   * `Sample1 = BaseValue - (B >> 4)`
   * `cmp (B & 0x0F), 0x0F; je skip` (`0x004c52b3` - Füllnibble-Uebersprung)
   * `Sample2 = BaseValue - (B & 0x0F)`

### A.6 Analyse und Deaktivierung der Loeschbefehle

Beim regulaeren Download sendet `SpO2.exe` nach Empfang aller Datenbloecke automatisch die Befehle `0x91..0x96` (User-Loeschung) und `0x8E` (Parameter 3, 6, 7) ueber den Dispatcher `0x0049baa9`.
Der erstellte Binary-Patch installiert einen Inline-Hook im freien Codebereich (`0x00558cd0`):
```x86
0x00558cd0: mov  eax, dword ptr [esp + 4]    ; Befehls-Opcode
0x00558cd4: cmp  eax, 0x91
0x00558cd9: jb   check_8e
0x00558cdb: cmp  eax, 0x96
0x00558ce0: jbe  drop_cmd                    ; Verwirft 0x91..0x96
check_8e:
0x00558ce2: cmp  eax, 0x8e
0x00558ce7: jne  passthrough
0x00558ce9: mov  edx, dword ptr [esp + 0x10] ; Parameter 3/6/7 (Loeschen)
0x00558cf0: je   drop_cmd
passthrough:
0x00558cfc: push ebp                         ; Originalcode ausfuehren
0x00558d06: jmp  0x0049bab3
drop_cmd:
0x00558d0b: xor  eax, eax
0x00558d0d: ret  0x18                        ; Lautlos verwerfen
```
Dadurch bleibt der Geraetespeicher nach jedem Download zu 100% intakt.
